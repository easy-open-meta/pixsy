为「自己管图」设计的每一步

从落盘到外链，每个决定都指向同一个目标：少依赖、少操心、搬得走。

单二进制部署

前端经 go:embed 内嵌进二进制，一个文件就是整站。拷贝、运行、完事。

零外部依赖

SQLite 用纯 Go 驱动（无 CGO），存储就是本地磁盘。交叉编译任意平台无障碍。

内容寻址去重

按 SHA-256 哈希落盘，同一张图传一百次只存一份；删到没人引用才真正删除。

自动缩略图

上传即生成 350px JPEG 缩略图，列表页刷得飞快，原图按需加载。

旧链接无缝衔接

从 Lsky Pro 迁移自动记录路径别名，换域名后历史文章里的 /i/… 链接照常可用。

四种外链一键复制

URL / Markdown / HTML / BBCode，写博客、发论坛、贴聊天，各取所需。

多用户与权限

JWT 认证、登录接口限速防爆破；首个注册用户自动成为管理员。

在线管理后台

站点名称、注册/上传开关、单图与批量上限，改完即时生效，无需重启。

外链防盗链

访客 IP/网段、引用站点域名双白名单与仅嵌图模式（防 F12 新标签页打开）；白名单外的请求返回空内容，登录用户不受限。

5 分钟部署

三条路都能走：容器、单文件、源码构建。数据就是 data/ 一个目录，备份它等于备份全站。

# 最快：直接拉取 Docker Hub 镜像
docker pull yjj6731/pixsy:latest
docker run -d -p 8080:8080 -v ./data:/app/data yjj6731/pixsy:latest

# 或 docker compose（已含数据卷与重启策略）
docker compose up -d --build

# 或手动构建运行
docker build -t pixsy .
docker run -d -p 8080:8080 -v ./data:/app/data pixsy
# Linux / Windows 产物为 CGO_ENABLED=0 静态单文件（约 12MB）
# 版本号以 Releases 页为准：gitee.com/java-and-net/pixsy/releases
wget https://gitee.com/java-and-net/pixsy/releases/download/v1.0.0/pixsy-linux-amd64
chmod +x pixsy-linux-amd64
./pixsy-linux-amd64          # 默认监听 :8080，数据在 ./data

# systemd 常驻：unit 文件见 deploy/pixsy.service
# 1. 构建前端（输出 web/dist，供 go:embed 内嵌）
npm --prefix web install
npm --prefix web run build

# 2. 编译后端并运行
go build -o pixsy ./cmd/pixsy
./pixsy

打开 http://localhost:8080 —— 首个注册的用户自动成为管理员。

生态与迁移

从旧图床搬家，或者把博客的上传接过来，都是一条命令的事。

emlog 插件

博客上传直接进图床

emlog 后台装上插件，资源上传整体接管到 pixsy，文章里写的就是图床外链。

  • 上传接管：媒体库 / Markdown 编辑器统一生效
  • 图库导入：把 pixsy 已有图片批量登记进 emlog 资源库
  • 删除联动：删博客资源时同步删除图床图片
  • token 自动续期，含钩子排位自检
Lsky Pro 迁移

换图床，不断链

管理后台填入 Lsky Pro 地址与账号，可视化管理整个迁移过程。

  • 进度实时可见，随时取消
  • 旧路径别名自动记录，历史文章外链照常可用
  • 迁移完成后可下载「旧 URL → 新 URL」映射 CSV
  • 同哈希幂等，重复执行不产生重复文件

干净的 API

统一 JSON 包络：成功 {"data": …}，失败 {"error": {code, message}}；鉴权走 Bearer token。

POST/api/v1/images上传图片（multipart 字段 file，可批量）
GET/api/v1/images图片列表，分页；管理员可 scope=all
DELETE/api/v1/images/{id}删除图片
GET/i/{hash}.{ext}原图直出（支持 HTTP Range）
GET/t/{hash}.jpg缩略图直出

完整接口清单见 README · API，或直接看 api.go 源码。

1. pixsy 是什么？

pixsy 是一个「图床」：把你的图片存到上面，然后给你一个网址链接，你可以把这个链接贴到博客、论坛、微信公众号排版工具等任何地方，图片就能显示出来。

它和「免费图床网站」的区别是：pixsy 跑在你自己的电脑或服务器上，图片存在你自己的硬盘里——

  • 不用担心第三方图床跑路、限速或者加广告水印；
  • 一个文件（约 12MB 的 exe 或约 25MB 的 Docker 镜像）就是整个网站，不用安装数据库；
  • 支持的图片格式：JPEG / PNG / GIF（动图）/ WebP / ICO；
  • 上传后自动生成缩略图，图片多了以后列表页也刷得快；
  • 内容相同的图片自动去重，不会重复占用硬盘。

2. 安装部署（三选一）

三种方式装出来的功能完全一样，选一种顺手的即可。装好后打开 http://localhost:8080 能看到 pixsy 首页，就说明成功了。

方式 A：Windows 电脑（最简单，双击就能用）

适合：本地自用、内网使用、想先试试看。

  1. 拿到程序：从 Releases 页面 下载 pixsy_windows_amd64.zip（或在仓库根目录执行 make package 自行打包）。
  2. 解压：把压缩包解压到一个固定的文件夹，比如 D:\pixsy\。里面就一个文件：pixsy-windows-amd64.exe。
  3. 双击运行：第一次运行会弹出 Windows 防火墙提示——只在自己电脑上用就点「取消」；想让局域网里其他设备（如手机）访问，勾选「专用网络」后点「允许访问」。
  4. 程序会自动打开浏览器进入 pixsy 首页；没弹出来的话，手动访问 http://localhost:8080。

想换端口？在 exe 旁边新建一个文本文件，改名并保存为 pixsy.json，内容写成：

{ "port": 9000 }

重新双击 exe，就改用 9000 端口了（完整选项见 配置附录）。

想开机自动启动？用 Windows「任务计划程序」注册一次即可，管理员 PowerShell 里执行（把路径换成你的）：

schtasks /Create /TN pixsy /SC ONSTART /RU SYSTEM /TR "D:\pixsy\pixsy-windows-amd64.exe --addr :8080 --data D:\pixsy\data"

提示：程序本身是前台黑窗口，双击运行时关掉窗口 = 停止服务，不是崩溃，重新双击即可。

方式 B：有服务器（Linux）—— 正式使用推荐

适合：有一台云服务器 / NAS / 树莓派，想 7×24 挂着给博客供图。

  1. 上传并安装（以下命令在服务器上执行）： 
    # 上传 pixsy_linux_amd64.tar.gz 到服务器后：
tar -xzf pixsy_linux_amd64.tar.gz          # 解压出 pixsy 可执行文件
sudo useradd -r -s /usr/sbin/nologin pixsy  # 创建专用的低权限运行账号
sudo mkdir -p /opt/pixsy/data
sudo install -m 0755 pixsy /opt/pixsy/pixsy
sudo chown -R pixsy:pixsy /opt/pixsy

    ARM 设备（部分 NAS / 树莓派）请用 pixsy_linux_arm64.tar.gz。

  2. 注册成系统服务（开机自启、崩了自动拉起）： 
    sudo cp deploy/pixsy.service /etc/systemd/system/pixsy.service
sudo systemctl daemon-reload
sudo systemctl enable --now pixsy
sudo systemctl status pixsy   # 看到 active (running) 就成功了
  3. 验证：浏览器打开 http://服务器IP:8080，或在服务器上执行 curl http://127.0.0.1:8080/api/v1/config，返回一段 JSON 即表示服务正常。

之后改了配置（端口、数据目录等），执行一次 sudo systemctl daemon-reload 再 sudo systemctl restart pixsy 生效。

安全提醒：如果服务器有防火墙/安全组（如阿里云、腾讯云），记得在控制台放行 8080 端口，否则外网访问不了。

方式 C：Docker（懂容器的一分钟部署）

已有镜像在 Docker Hub：yjj6731/pixsy。

# 最快方式：docker run
docker run -d -p 8080:8080 -v ./data:/app/data --restart unless-stopped yjj6731/pixsy

# 或在本项目目录用 docker compose（会本地构建镜像）
docker compose up -d --build

数据（数据库 + 图片）持久化在宿主机 ./data 目录，升级镜像不会丢。需要自定义时通过环境变量传入：

environment:
  - PIXSY_BASE_URL=https://img.example.com   # 图片外链前缀（挂了 CDN 域名时设置）
  - PIXSY_JWT_SECRET=改成一段随机字符串        # 生产环境建议显式指定

3. 第一次使用：注册与登录

  1. 打开 pixsy 首页（http://localhost:8080 或你的服务器地址）。
  2. 点右上角「注册」，填 用户名、密码、确认密码，点「注册」。
  3. 注册成功会自动登录，直接进入上传页面。

⭐ 重要：第一个注册的用户自动成为管理员。所以自己的服务，装好后第一件事就是去注册，管理员身份就是你的了。之后注册的都是普通用户。

后台可以随时关闭开放注册（见 管理员后台），关闭后只有已有账号能登录——个人自用建议注册完就关掉，防止陌生人来传图。

4. 日常使用：上传图片、拿外链、管理图片

4.1 上传图片

  1. 点「选择图片」按钮，在弹出的文件窗口里按住 Ctrl（或 Shift）可以一次选中多张。
  2. 页面顶部会显示当前规则：单图 ≤ 20 MB · 单批最多 10 张（管理员可在后台修改这两个上限）。
  3. 每个文件一行，各自有进度条，一张传完自动传下一张；传完显示「完成」。失败会直接标注原因，例如「超过单图 20 MB 上限」；如果图片在 OneDrive 等云盘的「按需下载」目录里（本地只是占位图标），会提示先同步回本地。

上传完成后，新图片会自动出现在下方「我的图片」列表里。

4.2 获取外链（重点！）

「我的图片」里每张图都是一张卡片：

卡片元素说明
缩略图点它可放大预览
文件名 / 大小 · 尺寸如 64.7 KB · 300×200
BBCode 按钮点一下复制 BBCode 链接（论坛常用），按钮短暂变成「已复制」
Markdown 按钮点一下复制 Markdown 链接（博客、笔记常用）
Markdown:  ![文件名](http://你的域名/i/xxxx.png)
BBCode:    [img]http://你的域名/i/xxxx.png[/img]

想直接要图片网址（URL）？点缩略图放大预览，点「打开原图」会在新标签页打开图片本体，浏览器地址栏里就是纯图片 URL，直接复制即可。

💡 小知识：每张图片的外链地址形如 /i/一串字母数字.png，这串字符由图片内容计算得出。就算你把文件名改了、重新上传同一张图，内容相同就共享同一个地址，不会重复占空间。

4.3 预览与删除

  • 预览：点卡片上的缩略图，弹出大图浮层，显示原图、文件名、大小、尺寸；可点「打开原图」在新标签页查看，点「关闭」退出。
  • 删除：点卡片上的「删除」，会弹确认框「确定删除……删除后不可恢复」，确认后图片被移除。⚠️ 删除是真正的删除（按内容哈希去重存储，只有当同一内容没有其他引用时文件才真正从硬盘移除），且没有回收站，删前想清楚。

4.4 图片多了以后

  • 列表自动分页，底部「上一页 / 下一页」翻页，显示当前页码。
  • 管理员在列表上方多一个「我的 / 全部」切换：「我的」看自己传的，「全部」能浏览全站所有人传的图（也能管理/删除）。

5. 管理员后台

用管理员账号登录后，右上角导航会多出「后台」入口，点进去有两块功能。

5.1 站点设置

设置项默认值作用
站点名称pixsy显示在页面左上角，随你喜欢改
允许新用户注册开关掉后注册页不可用，只有老账号能登录（个人自用建议关）
允许上传图片开全站上传总开关，紧急情况可一键停上传
单图大小上限（MB）20单个文件最大多大（1~1024）
单批上传数量上限10一次最多同时选几张（1~50）
外链 IP 白名单空防盗链：填访客 IP 或网段（如 203.0.113.7、192.168.1.0/24，每行一个），只有这些网络能加载外链图片，其余请求返回空内容
外链引用域名白名单空防盗链：填允许嵌图的站点域名（如 example.com，每行一个，子域名自动放行），这些站点页面里的图片对它的所有访客可见
仅允许嵌图加载关防盗链：开启后，用开发者工具/右键「在新标签页打开图片」或地址栏直接打开图片会返回空内容，只有网页里的图片元素能正常加载

改完点「保存设置」，立即生效，不用重启程序。

关于防盗链（两个白名单 + 仅嵌图）：

  • 全部留空/关闭 = 不启用检测，行为与从前完全一样；启用后命中任意一项白名单即可访问。
  • 「外链 IP 白名单」控制哪些网络的访客能看到图——嵌图页面里是访客的浏览器直接来取图，看的是访客的 IP，不是对方网站服务器的 IP。适合"只允许公司/家里网络查看"。
  • 「外链引用域名白名单」控制哪些网站可以嵌图——填了 example.com，它页面里的图片对所有访客可见；其他站点嵌图显示为空白；地址栏直开、RSS/Markdown 阅读器等无来源页面场景不受影响。
  • 「仅允许嵌图加载」利用浏览器强制的 Sec-Fetch-Dest 标记区分"网页里的图片"与"独立页面打开"：开启后从白名单站点用 F12/右键新标签页打开图片也会被拦；同时地址栏直接打开也会失效（两者在服务端不可区分），RSS 阅读器、老浏览器等不上报该标记的客户端不受影响。
  • 登录用户（含管理员）不受以上限制，图库里看原图与「打开原图」都正常；图片部署在 Nginx/Caddy 等反代之后时需设置 trusted_proxies，否则 IP 白名单看到的全是代理地址而非访客真实 IP。

5.2 站点行为小抄

  • 服务器重启后，以上设置依然保留（存在数据库里）。
  • 登录接口有防暴力破解限速：密码连续输错太快会被暂时拒绝，稍等即可。

6. 从 Lsky Pro（兰空图床）迁移旧图

如果你原来用兰空图床（Lsky Pro），换到 pixsy 后不用一张张重传，管理员后台就带迁移工具：

  1. 进入 后台 → 从 Lsky Pro 迁移图片。
  2. 填三项：Lsky 地址（如 https://img.example.com）、Lsky 登录邮箱、Lsky 密码。
  3. 点「开始迁移」。

之后会发生什么：

  • 迁移在服务器后台进行，关掉浏览器页面也不影响进度；回到后台页可以看到进度条和「已完成 x / y」实时状态。
  • 图片会导入到当前这个管理员账号名下。
  • pixsy 会自动记录旧站路径别名：老文章里的 /i/… 链接换成 pixsy 域名后照常能打开，不用逐篇改文章。
  • 个别图片失败不会中断整体迁移，结束后可展开「失败明细」查看原因。
  • 迁移完成后可下载「映射 CSV」（旧链接 → 新链接对照表），需要批量替换文章链接时用它配合文本替换工具即可。
  • 迁移过程中随时可以点「取消迁移」停下（已传好的不受影响）。

迁移的前提：pixsy 所在服务器能访问到旧 Lsky 站点；旧站账号里有对应的图片。不想用网页界面，也可以用仓库自带的命令行脚本 scripts/migrate-lsky.mjs 达到同样效果。

7. 数据备份与升级

备份 = 复制一个文件夹

pixsy 的全部数据都在数据目录（默认是程序旁边的 data\ 文件夹，Linux 默认 /opt/pixsy/data）：

data/
├── pixsy.db      # 数据库（账号、图片记录、站点设置）
├── jwt.secret    # 登录凭证密钥
├── files/        # 图片原图
└── thumbs/       # 缩略图

定期把这个文件夹整个复制走（或压缩）就是完整备份，恢复时放回原处即可。

升级

  1. 备份 data 目录（求稳的话）。
  2. 用新版本的 exe / 二进制 / 镜像替换旧程序文件（数据目录别动、别删）。
  3. 重新启动。旧数据、账号、图片全部保留。

8. 常见问题 FAQ

Q：打开页面提示「连接被拒绝」？
A：程序没在运行。Windows 双击 exe 看黑窗口是否一闪而过（可能端口被占用，按下一问改端口）；Linux 用 systemctl status pixsy 看服务状态。

Q：8080 端口被别的程序占了？
A：在 exe 旁边放一个 pixsy.json，写 { "port": 9000 }，重启程序后改用 9000 端口。

Q：上传按钮点不动 / 提示不允许上传？
A：管理员后台把「允许上传图片」关了，或「单图大小上限」设得太小。

Q：忘记管理员密码怎么办？
A：程序没有「找回密码」功能（数据都在你手里）。如果还没关注册，重新注册一个账号，再请懂数据库的人帮你把新账号提为管理员；或者干脆用备份的 data 目录回滚。

Q：图片外链在别的网站显示不出来？
A：按顺序检查——① 外链是不是复制的图片地址（/i/… 开头）；② 你的 pixsy 是否只有你自己能访问（局域网/本机部署），别人访问不到你的电脑；③ 是否设置了 HTTPS 混合内容问题（你的网站是 https，而图片链接是 http，浏览器会拦截）。

Q：想让图片走 CDN / 独立域名？
A：启动时设置 PIXSY_BASE_URL（或配置文件里的 base_url）为你的 CDN 域名，生成的外链会自动带上这个前缀。

Q：Windows 双击运行后黑窗口是什么？
A：那就是程序本体。关掉窗口服务就停了。想让它后台常驻，用第 2 节的任务计划方法，或直接用 Docker。

1. What is pixsy?

pixsy is an "image host": you store your pictures on it, it gives you back a web link, and you paste that link anywhere — a blog, a forum, a newsletter editor — and the image shows up.

The difference from free public image hosts: pixsy runs on your own computer or server, and your pictures stay on your own disk —

  • No worries about a third-party host shutting down, throttling you, or stamping ads/watermarks on your images;
  • One file (a ~12MB exe, or a ~25MB Docker image) is the whole site — no database to install;
  • Supported formats: JPEG / PNG / GIF (animated) / WebP / ICO;
  • Thumbnails are generated automatically on upload, so the library stays fast even with thousands of images;
  • Identical images are deduplicated by content, so nothing is ever stored twice.

2. Installation (pick one of three)

All three options produce exactly the same site. When you open http://localhost:8080 and see the pixsy home page, you're done.

Option A: Windows PC (easiest — just double-click)

Best for: personal use, LAN use, or just trying it out.

  1. Get the program: download pixsy_windows_amd64.zip from the Releases page (or run make package in the repo to build it yourself).
  2. Unzip it into a permanent folder, e.g. D:\pixsy\. Inside there's a single file: pixsy-windows-amd64.exe.
  3. Double-click to run. The first launch triggers a Windows Firewall prompt — only using it on this computer → click Cancel; want other devices (e.g. your phone) on the LAN to access it → check "Private networks" and click Allow access.
  4. The program automatically opens your browser to the pixsy home page. If nothing pops up, visit http://localhost:8080 yourself.

Want to change the port? Create a text file named pixsy.json next to the exe with just one line:

{ "port": 9000 }

Double-click the exe again and it now uses port 9000 (full reference in the configuration appendix).

Want it to start on boot? Register it once with Windows Task Scheduler. In an administrator PowerShell (adjust the path to yours):

schtasks /Create /TN pixsy /SC ONSTART /RU SYSTEM /TR "D:\pixsy\pixsy-windows-amd64.exe --addr :8080 --data D:\pixsy\data"

Note: the program runs as a foreground console window. Closing the window stops the service — that's not a crash; just relaunch it.

Option B: A server (Linux) — recommended for real use

Best for: a cloud VPS / NAS / Raspberry Pi that stays on 24/7 serving images for your blog.

  1. Upload and install (run on the server): 
    # after uploading pixsy_linux_amd64.tar.gz to the server:
tar -xzf pixsy_linux_amd64.tar.gz           # extracts the pixsy executable
sudo useradd -r -s /usr/sbin/nologin pixsy  # dedicated low-privilege run account
sudo mkdir -p /opt/pixsy/data
sudo install -m 0755 pixsy /opt/pixsy/pixsy
sudo chown -R pixsy:pixsy /opt/pixsy

    On ARM devices (some NAS / Raspberry Pi), use pixsy_linux_arm64.tar.gz instead.

  2. Register it as a system service (auto-start on boot, auto-restart on crash): 
    sudo cp deploy/pixsy.service /etc/systemd/system/pixsy.service
sudo systemctl daemon-reload
sudo systemctl enable --now pixsy
sudo systemctl status pixsy   # you want to see active (running)
  3. Verify: open http://<server-ip>:8080 in a browser, or run curl http://127.0.0.1:8080/api/v1/config on the server. A JSON response means everything works.

If you change the config (port, data directory, etc.) later, run sudo systemctl daemon-reload followed by sudo systemctl restart pixsy.

Security reminder: if your server has a firewall / cloud security group (Alibaba Cloud, Tencent Cloud, AWS, …), remember to open port 8080 there, or the outside world can't reach the site.

Option C: Docker (one-minute deploy if you know containers)

An image is published on Docker Hub: yjj6731/pixsy.

# Quickest: docker run
docker run -d -p 8080:8080 -v ./data:/app/data --restart unless-stopped yjj6731/pixsy

# Or use docker compose from this project's directory (builds the image locally)
docker compose up -d --build

Data (database + images) is persisted in the host's ./data directory and survives image upgrades. Customize via environment variables:

environment:
  - PIXSY_BASE_URL=https://img.example.com   # public URL prefix for image links (set when behind a CDN domain)
  - PIXSY_JWT_SECRET=change-to-a-random-string # recommended to set explicitly in production

3. First use: register and log in

  1. Open the pixsy home page (http://localhost:8080 or your server's address).
  2. Click Register in the top-right corner, fill in a username, password, and confirm password, then click Register.
  3. On success you're logged in automatically and land on the upload page.

⭐ Important: the first registered user automatically becomes the admin. So on your own installation, register first — admin is yours. Everyone who registers afterwards is a regular user.

You can turn off open registration any time in the admin panel (see Admin panel). Once closed, only existing accounts can log in — for personal use, it's a good idea to close it right after you register, so strangers can't upload to your host.

4. Everyday use: upload, get links, manage images

4.1 Uploading images

  1. Click the Select images button; hold Ctrl (or Shift) in the file picker to choose multiple files at once.
  2. The page shows the current limits up top: single image ≤ 20 MB · up to 10 per batch (an admin can change both limits in the admin panel).
  3. Each file gets its own row with its own progress bar; files are uploaded one by one and marked Done when finished. Failures state the reason directly, e.g. "exceeds the 20 MB per-image limit". If an image lives in a "files on demand" cloud folder (e.g. OneDrive with only a placeholder on disk), you'll be asked to sync the file back to local storage first.

Once uploaded, new pictures appear immediately in the My images list below.

4.2 Getting a link (the whole point!)

Every picture in "My images" is a card:

Card elementWhat it does
ThumbnailClick to open the large preview
Filename / size · dimensionse.g. 64.7 KB · 300×200
BBCode buttonCopies the BBCode link (used by many forums); the button briefly turns into "Copied"
Markdown buttonCopies the Markdown link (blogs, notes, docs)
Markdown:  ![filename](http://your-domain/i/xxxx.png)
BBCode:    [img]http://your-domain/i/xxxx.png[/img]

Just want the plain image URL? Click the thumbnail to open the large preview, then click Open original — the picture opens in a new tab and the browser's address bar holds the plain image URL, ready to copy.

💡 Good to know: every link looks like /i/a-string-of-characters.png, where the string is computed from the image's content. Rename the file or re-upload the same picture — identical content shares the same address and never wastes disk space.

4.3 Preview and delete

  • Preview: click a card's thumbnail to open a lightbox with the full-size image, filename, size, and dimensions. Click "Open original" to view it in a new tab, or "Close" to exit.
  • Delete: click Delete on the card. A confirmation appears — "Delete …? This cannot be undone." Deletion is real (thanks to content-hash deduplication, the file only leaves the disk when no other record references the same content), and there is no recycle bin — think before you confirm.

4.4 When your library grows

  • The list paginates automatically: Previous / Next buttons at the bottom, plus the current page number.
  • Admins get an extra Mine / All switch above the list: "Mine" shows your own uploads, "All" browses every image on the site (which you can also manage/delete).

5. Admin panel

After logging in with the admin account, an Admin panel entry appears in the top-right navigation. Inside there are two sections.

5.1 Site settings

SettingDefaultWhat it does
Site namepixsyShown in the top-left corner; call it whatever you like
Allow new registrationsOnWhen off, the register page is disabled and only existing accounts can log in (recommended for personal use)
Allow uploadsOnThe site-wide upload master switch — a one-click emergency stop
Max image size (MB)20Largest single file allowed (1–1024)
Max batch size10Most files selectable in one go (1–50)
Hotlink IP whitelistEmptyAnti-hotlinking: visitor IPs or CIDR ranges (e.g. 203.0.113.7, 192.168.1.0/24, one per line); only these networks can load image links, everyone else gets an empty response
Hotlink referer whitelistEmptyAnti-hotlinking: site domains allowed to embed your images (e.g. example.com, one per line, subdomains included); images embedded on those sites are visible to all of their visitors
Embedded loads onlyOffAnti-hotlinking: when on, opening an image as a standalone page (DevTools "open in new tab", right-click → new tab, address bar) returns an empty response; only image elements inside web pages load normally

Click Save settings and changes take effect immediately — no restart needed.

About hotlink protection (two whitelists + embedded-loads-only):

  • Leave everything empty/off = detection disabled, exactly the old behavior; when enabled, matching any one whitelist grants access.
  • The IP whitelist controls which networks' visitors can see the images — embedded <img> tags make the visitor's browser fetch the image directly, so it's the visitor's IP that matters, not the embedding site's server IP. Best for "only my office/home network may view".
  • The referer whitelist controls which sites may embed — with example.com listed, images on its pages are visible to all its visitors; embeds from other sites render blank; direct address-bar opens, RSS/Markdown readers and other no-referrer contexts are unaffected.
  • Embedded loads only uses the browser-enforced Sec-Fetch-Dest marker to tell "an image inside a web page" from "a standalone page": with it on, opening an image in a new tab from a whitelisted site (F12/right-click) is blocked too. Note it also disables direct address-bar access (the two are indistinguishable server-side); RSS readers and older browsers that don't send the marker are unaffected.
  • Logged-in users (admins included) are never restricted — viewing originals in the gallery and the "Open original" button keep working. When pixsy runs behind Nginx/Caddy, set trusted_proxies, otherwise the IP whitelist sees only the proxy's address instead of the visitor's real IP.

5.2 Behavior worth knowing

  • All of the above settings survive restarts (they're stored in the database).
  • The login endpoint is rate-limited against brute force: too many wrong attempts too quickly will be temporarily rejected — just wait a moment.

6. Migrating from Lsky Pro

Coming from Lsky Pro? No need to re-upload picture by picture — the admin panel has a built-in migration tool:

  1. Go to Admin panel → Migrate images from Lsky Pro.
  2. Fill in three fields: Lsky address (e.g. https://img.example.com), Lsky email, Lsky password.
  3. Click Start migration.

What happens next:

  • Migration runs in the background on the server; closing the browser does not stop it. Return to the admin page any time to see the progress bar and the live "completed x / y" counter.
  • Images are imported under the currently logged-in admin account.
  • pixsy automatically records path aliases for the old site: old /i/… links keep working after you switch the domain — no need to edit old articles one by one.
  • Individual failures never abort the whole migration; expand "Failure details" afterwards to see what went wrong.
  • Once finished, you can download the mapping CSV (old link → new link) and batch-replace links in your articles.
  • Click Cancel migration at any time to stop (whatever already transferred stays).

Requirements: the pixsy server must be able to reach the old Lsky site, and the Lsky account must own the images. Prefer a terminal? The bundled script scripts/migrate-lsky.mjs does the same thing from the command line.

7. Backup and upgrade

Backing up = copying one folder

Everything pixsy owns lives in the data directory (by default the data\ folder next to the program; /opt/pixsy/data on Linux):

data/
├── pixsy.db      # database (accounts, image records, site settings)
├── jwt.secret    # login-token signing key
├── files/        # original images
└── thumbs/       # thumbnails

Copy or zip this entire folder regularly and you have a full backup. To restore, put it back in place.

Upgrading

  1. Back up the data directory (to be safe).
  2. Replace the old program file (exe / binary / image) with the new version — don't touch or delete the data directory.
  3. Start it again. Accounts, settings, and pictures all carry over.

8. FAQ

Q: The page says "connection refused".
A: The program isn't running. On Windows, double-click the exe and watch whether the console window flashes and disappears (port already taken? see next question). On Linux, check systemctl status pixsy.

Q: Port 8080 is already in use.
A: Put a pixsy.json next to the exe containing { "port": 9000 }, restart, and the site moves to port 9000.

Q: The upload button does nothing / says uploads aren't allowed.
A: An admin turned off "Allow uploads" in the admin panel, or set the size limit too small.

Q: I forgot the admin password.
A: There's no password-recovery feature (all data is yours to manage). If registration is still open, register a fresh account and have someone comfortable with databases promote it to admin; otherwise restore from a backup of the data directory.

Q: Images don't show on the site where I pasted the links.
A: Check in order — ① the link is really the image address (starts with /i/…); ② your pixsy may only be reachable from your own machine/LAN, so visitors can't load it; ③ mixed-content blocking: your site is https but the image link is http, so the browser blocks it.

Q: Can images go through a CDN / custom domain?
A: Set PIXSY_BASE_URL at startup (or base_url in the config file) to your CDN domain; generated links will automatically carry that prefix.

Q: What is that black console window on Windows?
A: That's the program itself. Closing it stops the service. To run it as a background service, use the Task Scheduler method in section 2, or just use Docker.
