## 1. pixsy 是什么？

**pixsy 是一个"图床"：把你的图片存到上面，然后给你一个网址链接，你可以把这个链接贴到博客、论坛、微信公众号排版工具等任何地方，图片就能显示出来。**

它和"免费图床网站"的区别是：pixsy 跑在**你自己的电脑或服务器**上，图片存在你自己的硬盘里——

- 不用担心第三方图床跑路、限速或者加广告水印；
- 一个文件（约 12MB 的 exe 或约 25MB 的 Docker 镜像）就是整个网站，不用安装数据库；
- 支持的图片格式：**JPEG / PNG / GIF（动图）/ WebP / ICO**；
- 上传后自动生成缩略图，图片多了以后列表页也刷得快；
- 内容相同的图片自动去重，不会重复占用硬盘。

## 2. 安装部署（三选一）

> 三种方式装出来的功能完全一样，选一种顺手的即可。装好后打开 `http://localhost:8080` 能看到 pixsy 首页，就说明成功了。

### 方式 A：Windows 电脑（最简单，双击就能用）

适合：本地自用、内网使用、想先试试看。

1. **拿到程序**：从项目 [Releases 页面](https://github.com/easy-open-meta/pixsy/releases) 下载 `pixsy_windows_amd64.zip`（或在仓库根目录执行 `make package` 自行打包）。
2. **解压**：把压缩包解压到一个**固定的**文件夹，比如 `D:\pixsy\`。里面就一个文件：`pixsy-windows-amd64.exe`。
3. **双击运行**：第一次运行会弹出 Windows 防火墙提示——
   - 只在自己电脑上用 → 点「取消」即可；
   - 想让局域网里其他设备（如手机）访问 → 勾选「专用网络」后点「允许访问」。
4. 程序会**自动打开浏览器**进入 pixsy 首页；没弹出来的话，手动访问 `http://localhost:8080`。

**想让别人也能访问？** pixsy 默认监听 8080 端口。想换端口的话，在 exe 旁边新建一个文本文件，改名并保存为 `pixsy.json`，内容只要一行段：

```json
{ "port": 9000 }
```

重新双击 exe，就改用 9000 端口了（配置文件的完整选项见 [附录：配置一览](#附录配置一览)）。

**想开机自动启动？** 用 Windows 的「任务计划程序」注册一次即可，管理员 PowerShell 里执行（把路径换成你的）：

```powershell
schtasks /Create /TN pixsy /SC ONSTART /RU SYSTEM /TR "D:\pixsy\pixsy-windows-amd64.exe --addr :8080 --data D:\pixsy\data"
```

> 提示：程序本身是前台黑窗口，双击运行时**关掉窗口 = 停止服务**，不是崩溃，重新双击即可。

### 方式 B：有服务器（Linux）—— 正式使用推荐

适合：有一台云服务器 / NAS / 树莓派，想 7×24 挂着给博客供图。

1. **上传并安装**（以下命令在服务器上执行）：

```bash
# 上传 pixsy_linux_amd64.tar.gz 到服务器后：
tar -xzf pixsy_linux_amd64.tar.gz          # 解压出 pixsy 可执行文件
sudo useradd -r -s /usr/sbin/nologin pixsy  # 创建专用的低权限运行账号
sudo mkdir -p /opt/pixsy/data
sudo install -m 0755 pixsy /opt/pixsy/pixsy
sudo chown -R pixsy:pixsy /opt/pixsy
```

> ARM 设备（部分 NAS / 树莓派）请用 `pixsy_linux_arm64.tar.gz`。

2. **注册成系统服务**（开机自启、崩了自动拉起）：

```bash
sudo cp deploy/pixsy.service /etc/systemd/system/pixsy.service
sudo systemctl daemon-reload
sudo systemctl enable --now pixsy
sudo systemctl status pixsy   # 看到 active (running) 就成功了
```

3. **验证**：浏览器打开 `http://服务器IP:8080`，或在服务器上执行：

```bash
curl http://127.0.0.1:8080/api/v1/config
```

返回一段 JSON（站点配置）即表示服务正常。

之后改了配置（端口、数据目录等），执行一次 `sudo systemctl daemon-reload` 再 `sudo systemctl restart pixsy` 生效。

> **安全提醒**：如果服务器有防火墙/安全组（如阿里云、腾讯云），记得在控制台放行 8080 端口，否则外网访问不了。

### 方式 C：Docker（懂容器的一分钟部署）

已有镜像在 Docker Hub：`yjj6731/pixsy`。

```bash
# 最快方式：docker run
docker run -d -p 8080:8080 -v ./data:/app/data --restart unless-stopped yjj6731/pixsy

# 或在本项目目录用 docker compose（会本地构建镜像）
docker compose up -d --build
```

数据（数据库 + 图片）持久化在宿主机 `./data` 目录，升级镜像不会丢。需要自定义时通过环境变量传入（见 `docker-compose.yml` 内注释），常用的两个：

```yaml
environment:
  - PIXSY_BASE_URL=https://img.example.com   # 图片外链前缀（挂了 CDN 域名时设置）
  - PIXSY_JWT_SECRET=改成一段随机字符串        # 生产环境建议显式指定
```

## 3. 第一次使用：注册与登录

1. 打开 pixsy 首页（`http://localhost:8080` 或你的服务器地址）。
2. 点右上角「**注册**」，填 **用户名**、**密码**、**确认密码**，点「注册」。
3. 注册成功会自动登录，直接进入上传页面。

> ⭐ **重要**：**第一个注册的用户自动成为管理员**。所以自己的服务，装好后第一件事就是去注册，管理员身份就是你的了。之后注册的都是普通用户。

后台可以随时**关闭开放注册**（见 [管理员后台](#5-管理员后台)），关闭后只有已有账号能登录——个人自用建议注册完就关掉，防止陌生人来传图。

## 4. 日常使用：上传图片、拿外链、管理图片

### 4.1 上传图片

登录后首页就是上传页：

1. 点「**选择图片**」按钮，在弹出的文件窗口里按住 Ctrl（或 Shift）可以一次选中多张。
2. 页面顶部会显示当前规则：**单图 ≤ 20 MB · 单批最多 10 张**（管理员可在后台修改这两个上限）。
3. 每个文件一行，各自有进度条，一张传完自动传下一张；传完显示「完成」。
   - 传失败会直接标注原因，例如「超过单图 20 MB 上限」。
   - 特殊情况：如果你的图片存在 OneDrive 等云盘的"按需下载"目录里（本地只是个占位图标），上传前会提示你先把文件同步回本地。

上传完成后，新图片会自动出现在下方「**我的图片**」列表里。

### 4.2 获取外链（重点！）

「我的图片」里每张图都是一张卡片，上面有：

| 卡片元素 | 说明 |
| --- | --- |
| 缩略图 | 点它可放大预览 |
| 文件名 / 大小 · 尺寸 | 如 `64.7 KB · 300×200` |
| **BBCode** 按钮 | 点一下复制 BBCode 格式链接（论坛常用），按钮短暂变成「已复制」 |
| **Markdown** 按钮 | 点一下复制 Markdown 格式链接（博客、笔记常用） |

两种链接长这样（已自动填好你图片的真实地址）：

```
Markdown:  ![文件名](http://你的域名/i/xxxx.png)
BBCode:    [img]http://你的域名/i/xxxx.png[/img]
```

**想直接要图片网址（URL）？** 点缩略图放大预览，点「**打开原图**」会在新标签页打开图片本体，浏览器地址栏里就是纯图片 URL，直接复制即可。

> 💡 小知识：每张图片的外链地址形如 `/i/一串字母数字.png`，这串字符由图片内容计算得出。**就算你把文件名改了、重新上传同一张图，内容相同就共享同一个地址，不会重复占空间。**

### 4.3 预览与删除

- **预览**：点卡片上的缩略图，会弹出大图浮层，显示原图、文件名、大小、尺寸，可点「打开原图」在新标签页查看，点「关闭」退出。
- **删除**：点卡片上的「**删除**」，会弹确认框「确定删除……删除后不可恢复」，确认后图片被移除。⚠️ 删除是真正的删除（文件按内容哈希去重存储，只有当同一内容没有其他引用时文件才真正从硬盘移除），**且没有回收站**，删前想清楚。

### 4.4 图片多了以后

- 列表自动**分页**，底部「上一页 / 下一页」翻页，显示当前页码。
- **管理员**在列表上方多一个「**我的 / 全部**」切换：「我的」看自己传的，「全部」能浏览全站所有人传的图（也能管理/删除）。

## 5. 管理员后台

用管理员账号登录后，右上角导航会多出「**后台**」入口，点进去有两块功能。

### 5.1 站点设置

| 设置项 | 默认值 | 作用 |
| --- | --- | --- |
| 站点名称 | `pixsy` | 显示在页面左上角，随你喜欢改 |
| 允许新用户注册 | 开 | 关掉后注册页不可用，只有老账号能登录（个人自用建议关） |
| 允许上传图片 | 开 | 全站上传总开关，紧急情况可一键停上传 |
| 单图大小上限（MB） | 20 | 单个文件最大多大（1~1024） |
| 单批上传数量上限 | 10 | 一次最多同时选几张（1~50） |

改完点「**保存设置**」，**立即生效，不用重启程序**。

### 5.2 站点行为小抄

- 服务器重启后，以上设置依然保留（存在数据库里）。
- 登录接口有防暴力破解限速：密码连续输错太快会被暂时拒绝，稍等即可。

## 6. 从 Lsky Pro（兰空图床）迁移旧图

如果你原来用兰空图床（Lsky Pro），换到 pixsy 后不用一张张重传，管理员后台就带迁移工具：

1. 进入 **后台 → 从 Lsky Pro 迁移图片**。
2. 填三项：
   - **Lsky 地址**：旧图床的网址，如 `https://img.example.com`；
   - **Lsky 登录邮箱** / **Lsky 密码**：你原来登录兰空的账号密码。
3. 点「**开始迁移**」。

之后会发生什么：

- 迁移在**服务器后台**进行，**关掉浏览器页面也不影响进度**；回到后台页可以看到进度条和「已完成 x / y」实时状态。
- 图片会导入到**当前这个管理员账号**名下。
- pixsy 会自动记录旧站路径别名：**老文章里的 `/i/…` 链接换成 pixsy 域名后照常能打开**，不用逐篇改文章。
- 个别图片失败不会中断整体迁移，结束后可展开「失败明细」查看原因。
- 迁移完成后可下载「**映射 CSV**」（旧链接 → 新链接对照表），需要批量替换文章链接时用它配合文本替换工具即可。
- 迁移过程中随时可以点「**取消迁移**」停下（已传好的不受影响）。

> 迁移的前提：pixsy 所在服务器能访问到旧 Lsky 站点；旧站账号里有对应的图片。不想用网页界面，也可以用仓库自带的命令行脚本 `scripts/migrate-lsky.mjs` 达到同样效果。

## 7. 数据备份与升级

### 备份 = 复制一个文件夹

pixsy 的全部数据都在 **数据目录**（默认是程序旁边的 `data\` 文件夹，Linux 默认 `/opt/pixsy/data`）：

```
data/
├── pixsy.db      # 数据库（账号、图片记录、站点设置）
├── jwt.secret    # 登录凭证密钥
├── files/        # 图片原图
└── thumbs/       # 缩略图
```

**定期把这个文件夹整个复制走（或压缩）就是完整备份**，恢复时放回原处即可。

### 升级

1. 备份 `data` 目录（求稳的话）。
2. 用新版本的 exe / 二进制 / 镜像**替换旧程序文件**（数据目录别动、别删）。
3. 重新启动。旧数据、账号、图片全部保留。

## 8. 常见问题 FAQ

**Q：打开页面提示"连接被拒绝"？**
A：程序没在运行。Windows 双击 exe 看黑窗口是否一闪而过（可能端口被占用，按下一问改端口）；Linux 用 `systemctl status pixsy` 看服务状态。

**Q：8080 端口被别的程序占了？**
A：在 exe 旁边放一个 `pixsy.json`，写 `{ "port": 9000 }`，重启程序后改用 9000 端口。

**Q：上传按钮点不动 / 提示不允许上传？**
A：管理员后台把「允许上传图片」关了，或「单图大小上限」设得太小。

**Q：忘记管理员密码怎么办？**
A：程序没有"找回密码"功能（数据都在你手里）。简单粗暴的恢复办法：如果还没关注册，重新注册一个账号，再请懂数据库的人帮你把新账号提为管理员；或者干脆用备份的 `data` 目录回滚。

**Q：图片外链在别的网站显示不出来？**
A：按顺序检查——① 外链是不是复制的图片地址（`/i/…` 开头）；② 你的 pixsy 是否只有你自己能访问（局域网/本机部署），别人访问不到你的电脑；③ 是否设置了 HTTPS 混合内容问题（你的网站是 https，而图片链接是 http，浏览器会拦截）。

**Q：想让图片走 CDN / 独立域名？**
A：启动时设置 `PIXSY_BASE_URL`（或配置文件里的 `base_url`）为你的 CDN 域名，生成的外链会自动带上这个前缀。

**Q：Windows 双击运行后黑窗口是什么？**
A：那就是程序本体。关掉窗口服务就停了。想让它后台常驻，用第 2 节的任务计划方法，或直接用 Docker。

## 附录：配置一览

优先级：**命令行参数 > `PIXSY_*` 环境变量 > `pixsy.json` 配置文件 > 默认值**。

个人用户只需要关心这几项：

| 想改什么 | 怎么改 |
| --- | --- |
| 端口 | 配置文件 `"port": 9000`，或参数 `--addr :9000`，或环境变量 `PIXSY_ADDR` |
| 图片存哪里 | 配置文件 `"data": "D:/picdata"`，或参数 `--data`（默认程序旁边 `./data`） |
| CDN / 外链前缀 | 配置文件 `"base_url": "https://img.xxx.com"`，或环境变量 `PIXSY_BASE_URL` |
| 关闭自动开浏览器 | 配置文件 `"open_browser": false`，或参数 `--open-browser=false` |
| 站点设置（站名/开关/上限） | 优先在**网页后台**改，即时生效；配置文件里 `settings` 段写的项会在**每次启动时强制覆盖**网页设置，没写的项不受影响 |

完整示例 `pixsy.json`：

```json
{
  "port": 8080,
  "data": "./data",
  "base_url": "",
  "jwt_secret": "",
  "static_dir": "",
  "open_browser": true,
  "settings": {
    "site_name": "pixsy",
    "allow_register": true,
    "allow_upload": true,
    "max_upload_mb": 20,
    "max_batch": 10
  }
}
```

> ⚠️ `jwt_secret` 留空会自动生成并保存在数据目录，一般不用管；多实例/容器部署且想固定登录状态时才显式指定。`settings` 里的值填非法（比如上限超范围）会导致程序拒绝启动并提示原因——按提示改回来即可。
